## 1. 本次会话做了什么

起因：客户（Yukichai）微信反馈两条 —— ①「AI 感降低了很多，但脸会频繁出现这种」（附图：脸上一块**矩形暗色块**，俗称阴阳脸）；②「silkmomo 又连不上啦」（前端红色「生成失败 · 连接中断 … 点『生成剩余 4 张』继续」）。

### 1.1 批次 H（`c588a65`，已 commit + 已部署 success）

用「Workflow 四路诊断 + 四路对抗验证 + 离线真图复现」把双根因钉死后修复：

- **矩形色块根因**：`faceRect`（`boxToPixelRect(faceBox2d)`，margin=0）硬裁了 margin 4~8% 的椭圆，羽化实测**仅 1.1px**；侧脸档切口落在椭圆 alpha=0.976 处 ≈ 满强度台阶。叠加 `harmonizeFaceTone` 的参考环取样在脸**外圈**，`isSkinPixel` 只看色度不看亮度（深棕头发 (60,45,40) 也判为皮肤），实测参考环 **98.7% 样本落在帽子/头发/背景**，均值偏离真肤色 29.9，三通道 transferRatio 全撞 1.6 上限 → 脸区被推 14.6 ΔRGB。
- **生成失败根因**：`app/task/[id]/page.tsx` 里 fetch 的 `try/catch` 写在**分块 for 循环之外** → 任一块抖动就放弃整轮剩余块（= 客户看到的「生成剩余 4 张」）；且服务端长阶段只发 `': keep-alive'` **注释行**，只刷字节看门狗、刷不到事件看门狗。
- **修复**：架构改「**先对齐后合成**」（新增 `alignSwapTone`，参考取 pass1 脸**内**像素，YCbCr 中位数/MAD + tanh 软饱和）；新增 `buildFaceAlphaField`（布尔运算后**单次**高斯模糊，σ 下限实测校准 4→8px）；**删除 `harmonizeFaceTone`** 与三层软窗相乘；`faceRect` 共用椭圆 margin；七处长阶段 20s `data:` 心跳；每块独立 `AbortController`、单块失败只淘汰当前块；看门狗 70→120s / 600→150s；合成底图改无损 PNG（衣服是产品本体）；空产品图不再注入服装标签污染肖像卡等。
- **离线量化**：边界 ΔRGB 17.58→**1**、alpha 相邻跳变 0.915→**0.051**、脸区色偏 20.0→**4.65**、有效换脸区反增 **158%**。

### 1.2 架构探索：B2 方案（**未实施，仅离线验证，这是最重要的 open thread**）

批次 H 上线后用户提出架构级质疑并且**是对的**：

> 「为什么不是直接用深图（swap 图）？你自己去调 alpha、调边界，这始终是有问题的。目前看还是有一点点色差，只是不那么明显。」

论据成立：我们已为「局部合成」打了 7 个批次补丁（C/C.1/C.2/C.2.1/F/F.1/H），每次都留新伪影；而 Face-swap-V2 的输出**内部自洽零 seam**（它见过整图上下文），我们切开再贴等于人为制造接缝。

离线验证了三个变体（证据全在 `verify-0729-换脸架构实验/`）：

| 方案 | 脸区 vs swap 原生 | 配饰 vs pass1 | 结论 |
|---|---|---|---|
| A 直接交付 swap 全图 | 0（完美） | 帽 9.97 / 镜 13.98 / logo 20.1（**被重绘**） | 脸完美但配饰丢 |
| **B2 全图 − 完整配饰** | **0（逐像素未动）** | 核心区 **帽 0.131 / 镜 0.111 / logo 0.235**；整框均值 帽 2.65 / 镜 3.99 | **最优候选** |
| C 批次 H（线上） | 6.40（有残留色差） | 帽 0.512 / 镜 0 / logo 0 | 配饰完美但脸有色差 |

**B2 的关键点**（务必理解，用户曾误会过术语）：「从**可编辑区**减去完整配饰」＝ 配饰**不允许被换脸模型改动** ＝ **配饰完整保留原样**，不是把配饰去掉。整张图用 swap 的新像素，唯独帽子/墨镜用 pass1 的原像素。接缝因此从「脸颊中央」（人眼最敏感）挪到「帽檐/镜框轮廓」（高对比纹理，人眼不敏感）。

B2 已验证达标项：脸区逐像素 0 差异；衣服/背景/配饰框外 **1,484,730 像素全部 0 差异**；Prada logo 恢复（1.62）；墨镜 swap-only 边缘残影 **0%**；不需要 `alignSwapTone`（管线大幅简化）。

Codex 判定「B2 不通过」，但**它的判定标准有一处自相矛盾**，接手时要自己复核：它用「相对 swap 原生的新增 ΔRGB < 4」衡量接缝，而 B2 的**目的**就是把配饰从 swap 版改回 pass1 版 —— 这必然产生大梯度，那是**目的达成**而非伪影。真正该看的是肉眼有无可见接缝/双轮廓。Codex 报告的真实遗留问题只有两条：帽子仍有 **6.67%** 的 swap-only 边缘残留（可能形成局部双轮廓）、完整 bbox 内混入皮肤/头发导致整框均值偏高。

**中断点**：已生成四联对比图 `verify-0729-换脸架构实验/07_四方对比_配饰交界.jpg`（Pass1 / swap 直交付 / 批次H / B2，放大到帽檐+墨镜+上半脸），**但还没来得及看**。接手第一件事就是看它，判断 B2 能否上线。
